# Анализ retention и юнит-экономики e-commerce маркетплейса (Olist)

Полный цикл анализа данных бразильского маркетплейса Olist: от разведки сырых
данных в PostgreSQL до BI-дашборда — с целью оценить, насколько эффективно
площадка удерживает клиентов, и дать обоснованную рекомендацию бизнесу.

## Бизнес-задача

Маркетплейс Olist хочет понять, стоит ли инвестировать в программы удержания
клиентов (retention), или эффективнее продолжать фокус на привлечении новых
клиентов. Для ответа нужно оценить фактический уровень удержания, ценность
клиента на всём горизонте (LTV) и то, насколько эти показатели различаются
между регионами и категориями товаров.

## Данные

**Источник:** [Olist Brazilian E-Commerce](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) (Kaggle)
**Объём:** ~99 000 заказов, сентябрь 2016 — октябрь 2018
**Использованные таблицы:** customers, orders, order_items, order_payments,
products, category_translation

## Методология

```
PostgreSQL (SQL) → Python (pandas, seaborn, scipy) → Power BI
```

1. Разведка и очистка данных, проверка на дубликаты/NULL
2. Когортный анализ retention
3. Расчёт ключевых метрик: AOV, Repeat Purchase Rate, LTV
4. Статистическая проверка гипотез (Kruskal-Wallis)
5. BI-дашборд с ключевыми показателями

Все заказы отфильтрованы по статусу `delivered` — остальные статусы (canceled,
processing и т.д., ~3% от общего числа) исключены из анализа как незавершённые.

## Ключевые находки

**Retention критически низкий.** Repeat Purchase Rate ≈ 3% — то есть 97%
клиентов совершают ровно одну покупку и не возвращаются. Когортный анализ
подтверждает: retention падает практически до нуля уже в первый месяц почти
во всех когортах 2017–2018 года.

**LTV практически равен AOV.** Средний чек (AOV) ≈ R$159.9, LTV ≈ R$165.2 —
разница минимальна. Прямое количественное следствие низкого retention:
ценность клиента почти полностью исчерпывается его первой (и единственной)
покупкой.

**AOV значимо различается между регионами.** Статистический тест
(Kruskal-Wallis, p ≈ 2.4×10⁻¹⁷⁴) подтвердил, что различие в сумме заказа
между штатами не случайно. При этом лидеры по среднему чеку (PB, AC —
северо-восточные штаты) держатся на заметно меньших выборках заказов, чем
крупные штаты (SP, RJ, MG) — это важно учитывать при интерпретации.

**Выручка сконцентрирована в нескольких штатах.** São Paulo (SP) даёт почти
втрое больше выручки, чем второй по объёму штат (RJ) — ожидаемо для самого
населённого и экономически активного региона Бразилии.

**Средний чек и суммарная выручка категории — разные метрики.** Категории с
самым высоким средним чеком (computers) не совпадают с категориями,
приносящими наибольшую суммарную выручку (health_beauty, bed_bath_table) —
последние скорее массовые, чем дорогие.

## Рекомендации бизнесу

1. **Не рассчитывать на органический рост LTV за счёт удержания в текущем виде.**
   При retention ~3% усилия по привлечению новых клиентов приносят
   сопоставимую или большую отдачу, чем retention-программы для существующей
   базы — если только не удастся системно изменить паттерн одноразовых покупок.
2. **Разобраться в причинах низкого retention** — разовый характер покупок для
   многих категорий, отсутствие программы лояльности, опыт после первой
   покупки (задержки доставки, качество). Дальнейший анализ (например, связь
   review_score с повторными покупками) может дать более точный диагноз.
3. **Учитывать размер выборки при принятии решений по регионам** — не делать
   выводы о "премиальности" небольших штатов только по среднему чеку без
   поправки на объём наблюдений.

## Как воспроизвести

1. Скачать датасет с [Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)
2. Развернуть PostgreSQL, создать таблицы и загрузить CSV (схема — в `sql/01_schema_exploration.sql`)
3. Выполнить SQL-скрипты по порядку номеров
4. Открыть ноутбуки в `notebooks/` для когортного анализа и статистики
5. Импортировать CSV-выгрузки в Power BI для дашборда

## Стек технологий

`PostgreSQL` · `Python` (`pandas`, `numpy`, `seaborn`, `matplotlib`, `scipy`) · `Power BI`
